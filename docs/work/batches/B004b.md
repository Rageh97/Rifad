## Behavior

- Logger: one JSON line per entry with UTC `time`, `level`, `runtime`, lowercase dotted `event` and active context (`requestId`, `correlationId`, and tenant/device/user fields once the security pipeline sets them). Caller fields cannot overwrite reserved fields. Info/debug go to stdout, warn/error to stderr.
- Redaction: credential, session, cookie, API-key, cashier-PIN and card-data key names are replaced at any depth; Luhn-valid 13–19 digit runs in free text are masked; errors log only `name` and `code`. Output is bounded for depth, keys, items, string length and cycles.
- Roots: `runtime.started` / `runtime.failed` now use the logger (failure output stays value-free with no stack). The HTTP platform logs one `http.request.completed` line per request with method, path without query string, status and duration, inside the request's context.
- Data classes: public/internal/personal/sensitive/financial as fixed by the source. Adapters call `assertAllowed` before transfer: unknown processor, region outside policy, unapproved class or any unclassified field is rejected with a `forbidden` DomainError that does not echo values. No real processors or regions are registered; those await G07.

## Risk review

Assets: log output, outbound personal/financial data. Abuse cases and controls: secrets or card data in logs (key redaction, PAN masking, error message suppression; canary tests), log forging of context (reserved fields win; test), oversized/circular input (bounds; test), personal data sent to an unapproved processor/region (default-deny guard; tests), payload values echoed in rejections (test). Residual: key-name redaction is heuristic, so new sensitive field names must use recognizable names or be classified; the full PCI log-scan gate is M0-048. Retention (G02) and observability backend (G16) are not decided. Performance: one serialization per log line and one completion line per request; not measured beyond smoke, no SLO claimed.
