## Behavior

- Edge migration `0002_local_consumer_state`: `local_consumer_processed` and `local_consumer_position` in the encrypted store.
- `dispatchLocalEvents(store, consumers)` reads undispatched local events in commit `sequence` order. For each event, one immediate SQLite transaction:
  1. records delivery per subscribed consumer (redelivery skipped);
  2. for PER_AGGREGATE events applies the ordering guard (already-applied versions skipped);
  3. runs the consumer's synchronous `handle` and advances its position;
  4. marks the event dispatched.

  A gap rolls the event back and stops the pass, so nothing after it is dispatched out of order. `afterCommit` runs only after commit, for work outside the database such as realtime push or printing.
- `startLocalDispatcher` polls every 200 ms and reports dispatch counts, holds and errors. It has no Redis, BullMQ or Cloud dependency, so the branch keeps processing offline (ADR-041).

## Risk review

Failure cases: a crash mid-event (transaction rollback, redelivered on the next pass), duplicate dispatch (processed table), out-of-order effects (position guard and hold), a consumer exception (event stays pending, reported). Residual: a permanent hold stops later local events until resolved, which is deliberate for order safety but needs operator visibility (Edge observability, M4); handlers must be synchronous; no consumer is registered yet.
