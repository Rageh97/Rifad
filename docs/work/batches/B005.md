## Ownership and runtime

`@rifad/database` is `layer:infrastructure runtime:cloud`; Edge cannot depend on it (Nx rule plus architecture test), and Edge rejects `RIFAD_DATABASE_URL`. `@rifad/events` is a `layer:contract runtime:shared` envelope for both the Cloud outbox and the future Edge local outbox. Migration owners: `platform` (tenant-context function) and `events` (outbox). No context owns business data here; `fixture.settings` exists only inside the integration test database.

## Behavior

- Roles (§14.1): `rifad_owner` runs migrations and owns schemas/tables; `rifad_app` is the runtime role with LOGIN only (no superuser, BYPASSRLS, CREATEDB, CREATEROLE, inheritance or ownership) and explicit grants. Provisioning code is local/test-only and refuses non-loopback servers; production roles belong to future infrastructure.
- Tenant context: `rifad.current_organization_id()` reads a transaction-local setting; missing or empty means NULL, which matches no rows. `withTransaction(db, { organizationId } | 'platform', work)` sets it with `set_config(..., true)` and rolls everything back on error.
- Migrations: ordered `NNNN_name` IDs, SHA-256 checksums, one transaction under an advisory lock. Re-runs are no-ops; edited, removed or unordered migrations fail. Every tenant-owned table enables and forces RLS with a tenant policy in its creating migration.
- Outbox: `events.outbox` accepts only CLOUD and CLOUD_TO_EDGE planes (Edge events never use the Cloud relay, ADR-041). It is unique per tenant idempotency key and per aggregate version. RLS is forced. The runtime role may only SELECT/INSERT; publishing state changes wait for the relay (M0-021).
- Envelope: event ID, catalog type/version, plane, ordering scope (NONE/PER_AGGREGATE/PER_BRANCH), tenant/branch, aggregate type/ID/version, UTC occurredAt, correlation/causation, idempotency key; payload bounded to 64 KiB.
- Readiness: 200 only when the database answers within 2 s; otherwise 503 with `unavailable` or `not_configured`. Liveness and startup never wait for the database. Edge has no readiness route yet.
- Tooling: `pnpm db:migrate` with a loopback `RIFAD_DATABASE_OWNER_URL`.

## Risk review

Assets: tenant data isolation, event durability, database credentials. Actors: another tenant, a compromised runtime process, misconfiguration. Abuse cases and controls:

| Abuse case | Control and test |
| --- | --- |
| Cross-tenant read/write | Forced RLS; other-tenant and missing-context reads return 0 rows; writes fail `42501` |
| Runtime role escalation (UPDATE/DELETE, DDL, disabling RLS, metadata reads) | No grants; each attempt fails `42501`; role attribute audit |
| Pooled-connection context leak | Single-connection pool; context is NULL in the next transaction |
| Partial write | Rollback test for fixture row plus outbox |
| Duplicate or replayed events | Unique constraints raise `23505` |
| Edge-plane event in the Cloud relay | Rejected before any database call |
| Remote or production database from config | Loopback-only URL validation; errors never echo the value |
| Credentials in logs | The API/worker run with a real URL does not log the password |

The audit itself is proven to detect a table without RLS. A mutation run that weakened the outbox policy to `USING (true)` made the isolation test fail.

Residual: TLS, secret references and production role provisioning are not implemented (G16). The relay's cross-tenant read strategy (scoped service role) is a B006 decision. Performance: pool max 10, statement timeout 15 s, 2 s readiness probe. These are bounds, not measured SLOs (G02).

## Implementation choices

A small Docker CLI harness replaces the `testcontainers` package. It gives the same isolation (ephemeral container, random loopback port, tmpfs, synthetic credentials, forced removal) with no new dependency tree. The suite fails rather than skips when Docker is missing. Migrations are TypeScript string constants, so they ship in `dist` with checksums and need no file copying. `appendToOutbox` uses one parameterized SQL insert, so any Kysely instance or transaction can call it whatever its schema type (Kysely database generics are invariant). Integration specs (`*.integration.spec.ts`) are excluded from `pnpm check` and run by `pnpm test:integration`, one file at a time.

E03 (2026-11-02): `pg` 8.23.1 and `@types/pg` 8.23.1 are current. Kysely is pinned to 0.29.7, because 0.29.8 was published 2026-11-01, inside the two-week rule. PostgreSQL 18.6 is pinned by image digest.
