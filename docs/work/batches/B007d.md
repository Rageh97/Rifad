## Behavior

- **Audit** (`audit-contract`, `audit-infrastructure`; migration `0011_audit_trail`): `audit.audit_event` with actor user, action `<context>.<action>`, resource type/ID, outcome, request and correlation IDs and small details (≤ 4 KB), forced tenant RLS, runtime role SELECT/INSERT only (no UPDATE or DELETE).
  - Contexts receive an `AuditSinkFactory` from the composition root and record inside their own transaction, so an audited change and its record commit together. Context code depends only on the audit contract.
  - Recorded today:
    - Organizations: organization created/changed, branch opened/changed, member invited, membership changed.
    - Authorization: role defined/changed, role assigned/revoked.
    - Entitlements: feature set.
  - The actor comes from the request context (the verified user after the security pipeline; null for system actions such as bootstrap).
- **Bootstrap**: `pnpm admin:bootstrap -- --org … --timezone … --branch … --issuer … --subject …` with a loopback `RIFAD_DATABASE_OWNER_URL`, after `pnpm build` and `pnpm db:migrate`. It provisions the external identity (owner path; refuses an already provisioned identity), creates the organization and branch, activates the membership, defines an Owner role with every known permission, assigns it organization-wide, and enables every module, all audited. It prints the created IDs as one JSON line.
- `pnpm db:migrate` now applies migrations 0001–0011.

## Risk review

Abuse cases: tampering with history (no UPDATE/DELETE grant), cross-tenant reads of audit (forced RLS), audit gaps on partial failure (same transaction), sensitive data in audit (structured details only, size-bounded), bootstrap against a remote/production database (loopback-only) or twice for the same login (refused). Residual:
- Access denials are logged but not yet audited, because they happen outside a tenant transaction.
- Bootstrap runs several transactions, so a mid-way failure can leave a partial tenant that needs cleanup; a retry refuses the already provisioned identity.
- There is no audit retention policy yet (G02).
