## Behavior

- Organization: name 1–200 printable characters, IANA timezone, ACTIVE/SUSPENDED with explicit transitions, optimistic version. Its ID is created locally (ADR-017) and is the tenant context of its own creating transaction, so creation needs no RLS bypass.
- Branch: opened only in an ACTIVE organization; its organization never changes; optional timezone override (`branchTimezone` falls back to the organization's, ADR-016); ACTIVE → CLOSED.
- Membership: one live (non-ENDED) membership per user and organization, enforced by a domain check and a partial unique index; INVITED → ACTIVE/ENDED, ACTIVE ↔ SUSPENDED, any → ENDED (final). `canAct` is true only for an ACTIVE membership in an ACTIVE organization. Branch access comes from branch-scoped role assignments in Authorization (G13), not from Membership.
- Storage: schema `organizations`, forced tenant RLS on all three tables, runtime role with SELECT/INSERT and column-limited UPDATE, no DELETE (status changes keep history). Concurrent updates fail with `CONCURRENT_MODIFICATION`.
- Migrations: `pnpm db:migrate` now runs platform and Organizations migrations together in global ID order.

## Risk review

Abuse cases: cross-tenant read/write (forced RLS, repository also filters by organization), duplicate or concurrent invites (unique index → `MEMBERSHIP_EXISTS`), lost updates (version checks), suspended or ended members acting (`canAct` default deny; enforced in the pipeline in B007b), history deletion (no DELETE grant). Residual: finding a user's organizations at login needs a cross-tenant lookup that RLS forbids for the runtime role; that needs a scoped role or identity-side index in B007b. Performance: single-row statements by primary key; not measured.
