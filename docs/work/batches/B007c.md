## Behavior

- `@rifad/access` (`scope:shared`, contracts only): `createAccessPipeline(ports).authorize({ authorization, organizationId, branchId?, permission })`:
  1. `Bearer` token verified and resolved to a platform user, else `UNAUTHENTICATED` (401);
  2. requested organization (header `x-rifad-organization`) exists and is ACTIVE;
  3. the user has an ACTIVE membership in it;
  4. the permission's module is entitled;
  5. an optional branch (header `x-rifad-branch`) exists and is ACTIVE;
  6. a role assignment grants the permission at organization scope or for that branch.
  Steps 2–6 all fail with the same `ACCESS_DENIED` (403), so a denial never reveals whether an organization exists.
- `AccessGuard` (Nest): global and default-deny. A route must be `@PublicRoute()` or declare `@RequirePermission(...)`; anything else is refused. After success, `bindVerifiedIdentity` adds the verified user, tenant, branch and session to the request context, so logs, traces and RLS-scoped work use proven values; headers alone never set them.
- Kernel gains the `unauthenticated` error category (HTTP 401).
- API: with `RIFAD_DATABASE_URL` and all three `RIFAD_OIDC_ISSUER`/`RIFAD_OIDC_AUDIENCE`/`RIFAD_OIDC_JWKS_URL` (https, or http on loopback), the guard is installed and `GET /api/v1/organization` (`organizations.read`) is registered. Without them, no protected controller exists at all. Liveness is public; readiness is a Fastify route outside Nest guards.
- Architecture policy: composition roots (`layer:composition`, i.e. `apps/*`) are exempt from the scope-isolation rule because wiring contexts together is their job; every library keeps it, and Edge's ban on Cloud libraries is unchanged.

## Risk review

Abuse cases: missing or forged tokens (401), tenant hopping by header (membership + RLS), existence probing (uniform 403), suspended or ended members and suspended organizations (denied), disabled modules (denied before permission), branch-scope escalation (branch assignment never covers organization actions or other branches), unannotated routes (denied), identity spoofing through headers (context set only after verification). Residual: one DB transaction per check (organization, membership, entitlement, roles) without caching; no rate limiting; no token revocation; audit of denials is B007d.
