## Ownership and runtime

Shared kernel and platform code only; no context owns business state here and nothing is persisted. Kernel is `scope:shared layer:domain runtime:shared` and imports nothing outside itself. Request context and HTTP platform are `layer:infrastructure runtime:shared`, used by all three composition roots. Edge stays independently bootable with no Cloud, database, Redis or provider dependency.

## Behavior

- EntityId: canonical lowercase RFC 9562 UUIDs, generated locally (ADR-017); other input fails with `INVALID_ENTITY_ID`.
- Money: integer minor units (bigint) plus ISO currency; exact decimal parsing, no floating-point input, no rounding (rounding/tax/cash rounding await G04); cross-currency arithmetic fails. SAR is the baseline currency (ADR-019).
- Clock: UTC instants (ADR-016) with a fixed test clock. DomainEvent: catalog type `<context>.<name>.v<n>` (§33), version, positive aggregateVersion (ADR-033) and UTC occurredAt. Durable envelope fields belong to M0-019/032.
- DomainError: stable UPPER_SNAKE code plus domain category; Result is explicit success/failure.
- Request context: AsyncLocalStorage, server-generated requestId, caller correlation ID accepted only when single and well formed. Identity/tenant fields are never taken from headers; they are reserved for the authenticated pipeline (M0-016). Response headers carry both IDs.
- Errors: every failure, including routing and body-parsing errors, returns `{ error: { code, message, requestId } }`. Domain categories map to 400/403/404/409/422; transport errors use fixed messages; anything else is `INTERNAL_ERROR` with no stack, SQL or exception text.

## Risk review

Assets: request metadata, error output. Entry points: HTTP headers and bodies on loopback liveness roots. Abuse cases and controls: header-supplied tenant/user scope (ignored; test), oversized or injected correlation IDs (replaced, never echoed; tests), leakage through errors (fixed messages; SQL/stack/value canary tests), context bleed across concurrent requests (20 concurrent requests isolated; test). Residual: liveness remains unauthenticated and business-free; authorization is M0-013–016. Performance: one AsyncLocalStorage scope and two hooks per request; not measured beyond smoke, no SLO claimed (G02 open). Parent M0-005 propagation into logs and worker events needs M0-023/021.

## Implementation choices

Nest/Fastify integration lives in one shared library rather than three copies in the roots. Context is re-entered in `preHandler` as well as `onRequest` so it survives body parsing; the filter reads the requestId from the reply header so parse errors still carry it. Unit tests run through tsx with the base tsconfig because decorators are configured there.
