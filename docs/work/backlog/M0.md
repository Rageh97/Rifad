# M0 backlog and traceability

Source: v1.4 §31 (M0-001–051), §31.1, §36.2–36.3. This is a planning view. It grants no authorization, closes no parent task and does not replace the [M0 gate](../milestones/M0.md). Prerequisites and batch groupings are planning inferences, not source text; blockers refer to the [decision register](../decisions.md). A batch starts only after explicit user authorization.

## Status legend

- OPEN: parent acceptance criteria not yet executed. Completed child tasks are listed separately.
- Independent: source-fixed architecture is sufficient; no open business/compliance decision is required.
- Blocked: implementation depends on the named decision closing (or an approved nonblocking deferral).

## Traceability note: M0-054.a

v1.4 §31 ends at M0-051; there is no M0-054 row. B001 used `M0-054.a` for its local process workflow and smoke harness. It is retained as a historical identifier because B001 records, governance and CI evidence reference it. Traceability: it serves M0-002 acceptance (each application boots independently) and the process portion of M0-037 (integration harness). It does not complete either parent, and no further M0-054 children may be created.
